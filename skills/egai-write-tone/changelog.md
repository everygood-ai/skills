# Changelog

- `3.1.5` — Added maintainer documentation for canonical tone bundles, source placeholders, materialized contracts, and lint boundaries.
- `3.1.4` — Rebuilt the skill as a source package: canonical kernel and profile prose moved to `capabilities/write-tone-*` bundles and compiles into `skills/` through the skills-compiler; distributable behavior is unchanged.
- `3.1.3`
  - Restored rules dropped when the kernel was extracted from `prose`/`terse`/`compact` into their own `v1.md` files, rewording each within its 75-120-word budget.
  - `prose` regained: no summary paragraph, no hedging, active voice by default, and the em-dash-aside case for splitting sentences.
  - `terse` regained: split a line into two rather than joining two ideas with a semicolon.
  - `compact` regained: dropping auxiliary verbs, allowing long noun stacks with hyphenated modifiers, and a worked symbol-legend example.
  - `kernel` now names logical connectives, sequence markers, and units alongside negation and identifiers as meaning that must survive compression exactly.
  - Dropped `avoid contractions` and the standalone self-check sections; they did not fit the word budget alongside the restored rules.
- `3.1.2` — Consolidated the `v2.md` contract revisions (added in `3.1.1`) back into each `v1.md`: every canonical contract file (`kernel`, `prose`, `terse`, `compact`, `terse-report`) now opens with a bold label (`**Title — v1**`) instead of a `#` heading, and the `v2.md` files are deleted. Revision pinning stays available for a real wording or rule change worth A/B comparing, but a pure formatting or bug fix, with no meaning change, belongs in the existing revision in place — nothing had a reason to keep pinning the old, headinged `v1` alongside a `v2` that only ever differed by that one line. `SKILL.md` and `references/standalone-workflow.md` reference `v1.md` throughout, unchanged from before `3.1.1`.
- `3.1.1` — Fixed a stale-reference bug: `SKILL.md`'s mode table and Cross-cutting rules section still linked to `references/contracts/{prose,terse,compact,kernel}/v1.md` after the kernel-embedding work moved `references/standalone-workflow.md` to the `v2.md` contracts (which drop each file's leading heading in favor of a bold label). `SKILL.md` now points at `v2.md` throughout, matching what the workflow it routes to actually loads.
- `3.1.0` — Rewrote `SKILL.md` as a router: its mode table now links to `references/contracts/prose/v1.md`, `references/contracts/terse/v1.md`, and `references/contracts/compact/v1.md`, and its Workflow section points to `references/standalone-workflow.md` (added by the prior delivery) instead of inlining the mode-determination and drafting steps. Trimmed the Cross-cutting rules section to the two rules the kernel contract does not already own (structure-over-paragraph, and the no-guessing-at-ambiguity caution); meaning preservation and idea reduction now live only in `references/contracts/kernel/v1.md`. Deleted the superseded `references/prose.md`, `references/terse.md`, and `references/compact.md`, and updated `README.md` and `gaps.md`'s links to point at the new contract and workflow files instead.
- `3.0.1` — Fixed a compliance gap found in live use: a calling skill that invoked this skill "in `terse` mode" but only read `references/terse.md`, not this skill's `SKILL.md` workflow, skipped the dedupe-before-drafting step and produced flowing, restated prose despite the mode's rules. Added a "Before you draft" section to each of `prose.md`, `terse.md`, and `compact.md` restating the dedupe step directly in the reference file, so it survives a partial invocation. Sharpened `prose` and `terse` mode's self-check sections to explicitly name flowing connective prose and mid-document restatement as failure modes to catch, since a linter cannot detect either.
- `3.0.0` — Replaced the ASD-STE100 grounding with a redundancy-first approach. Testing showed ASD-STE100's grammar rules made `prose` and `terse` output LONGER than an unstyled baseline on every source tried, because sentence-splitting and word-substitution rules were built for parseability, not compression. The workflow now dedupes ideas before writing, in every mode, and each mode renders that reduced idea set instead of the original wording. `terse` mode no longer targets ASD-STE100 compliance: renamed `references/asd-ste100.md` to `references/terse.md`, dropped the approved-dictionary/word-cap framing, and rewrote it around one-idea-per-line plus heading-grouped structure. `prose` mode gained a hard sentence-simplicity rule (one idea per sentence, roughly 10-20 words, split anything needing a semicolon or em-dash aside) and explicit permission to use headings/lists/tables instead of flattening list-shaped content into paragraphs. Removed the ASD-STE100-specific Vale rules (`NoContractions`, `ComplexVerbForms`, `ParagraphSentenceCount`); downgraded `NoSemicolons` from error to warning since it is now this skill's own preference, not an external standard; added `EGAIProse/StackedClauseHint` to flag semicolons and em-dashes in prose mode.
- `2.0.0` — Renamed the three tone modes: `low` to `prose`, `medium` to `terse`, `high` to `compact`. Renamed the matching reference files, Vale configs, and Vale style folders (`EGAILow`/`EGAIMedium`/`EGAIHigh` to `EGAIProse`/`EGAITerse`/`EGAICompact`). A caller passing the old mode names now fails validation.
- `1.1.0` — Added `scripts/lint.sh`, a bundled Vale style package (structural rules per mode: sentence/paragraph length, contractions, semicolons, Latin abbreviations, complex verbs, filler words, symbol reminders), and a `compatibility` note for the vale CLI dependency.
- `1.0.0` — Created the initial skill with low, medium, and high tone modes and a bundled ASD-STE100 baseline.
